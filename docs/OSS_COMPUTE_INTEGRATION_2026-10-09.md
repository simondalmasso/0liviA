## Implemented in this change — lease ownership inspired by OpenMuse, *not* a copy

`Store.claim_queued_job(job_id, lease_seconds=120)` performs an **atomic SQL UPDATE** from `queued` to `running`, creating a random capability token that is never included in `get_job` / API payloads. Parallel Store instances cannot claim the same job twice.

`renew_job_lease`, `checkpoint_leased_job` and `finish_leased_job` require a matching, **unexpired** capability. `finish_leased_job` clears it and accepts only `complete`, `failed` or `cancelled`. Secret redaction still applies to persisted checkpoints. The older unconditional `checkpoint_job` is restricted from writing to jobs that currently have a lease; legacy unleased flows remain working.

Critically, a worker that disappears **does not trigger automatic replay** of an expired `running` job. External actions might have succeeded before the crash, so operators must inspect the external receipt before deciding to retry. This is intentional and is the safest default for code write, email, booking or other uncertain side effects.

Existing `server.py` coding/browser dispatch remains **legacy / unleased**; no automatic mutation or scheduler has been added. A future, separately tested change can opt in those call sites after validating exact run IDs, cancel/stop and idempotency for GitHub workflow dispatch. The SQLite additions are nullable and migrate existing v1 jobs without dropping or rewriting their checkpoints. No mandatory new package, network call, background loop, or cloud bill.

### Release / follow-up gates

1. Run Python CI 3.11/3.12 and security audit; concurrent Store handles must give exactly one successful claim; stale/foreign tokens must fail; migrated v1 DB retains jobs.
2. On canonical host, verify RAM, CPU, Linux capabilities, Docker/Podman and Landlock/seccomp **before** considering OpenShell. Keep current GitHub Actions worker if limits fail.
3. **Never** make OpenMuse Intelligence/cloud account, DigitalOcean, Dame, InternAI or AWS SES a dependency for owner login, memory or chat.
4. Once privileged SSH is recovered, run existing `preflight_only=true` on OCI issue #43. Core launch/backup/restore, provider no-overage, voice es-AR are still the real deployment gates.
5. Separate follow-up for opt-in leases in GitHub Actions coding/browser workflows with real receipt rechecks and external side-effect non-retry guarantees; avoid introducing duplicates on timeout.

## Costs and data protection

A price of USD 0 in a marketing trial is not a production no-overage guarantee. Every third-party processing location requires owner permission, verified plan, retention/data-residency policy, a non-billable hard-stop, and a disposable benchmark that does not involve memory, tokens or personal files. No registrations, checkouts, paid products or host mutations were authorized by this audit.
